# SL-3000 eMMC CI Implementation Plan

**Goal:** Build a pinned OpenWrt 25.12.5 / Linux 6.12 firmware with the approved applications, without changing other Kwrt targets or the router's bootloader/GPT.

**Architecture:** A standalone workflow uses official OpenWrt release feeds, pinned PassWall feeds and OpenClash, and a checksum-pinned Mihomo binary package. Device support is local and isolated. Existing common scripts and ABI bypasses are not invoked.

**Verification boundary:** Build tests cannot establish hardware stability. Initial releases are prereleases; RAM boot, Ethernet, both Wi-Fi bands, calibration and storage need physical acceptance before flashing.

## File Responsibilities

- `sources.lock.json`: exact source commits, release labels and binary checksum.
- `.config`: one target and required built-in applications.
- `prepare.py`: verified source checkout, feed installation and isolated device integration.
- `inject_defaults.py`, `firstboot.sh`: validated password injection and initial settings.
- `verify.py`: prebuild config and postbuild manifest/metadata/image checks; allowlisted export.
- `files/`, `image.mk`: DTS, board setup and partition-scoped upgrade support.
- `packages/mihomo/Makefile`: pinned aarch64 OpenClash Meta core.
- `tests/test_ci.py`: success and rejection cases using Python's standard library.
- `README.md`: trigger instructions, public setup-password warning, upgrade limits and hardware acceptance checklist.

## Confirmed Deviations From the Design

1. User explicitly chose a **public temporary Wi-Fi password** on 2026-09-05. Firmware necessarily contains it. `DEFAULT_WIFI_PASSWORD` is still validated and kept out of build logs and auxiliary artifacts.
2. Current RAM is 1 GiB; the reused DTS incorrectly describes 512 MiB.
3. Current GPT has only `kernel`, `rootfs`, `storage`; no `factory`. Current vendor driver logs show fallback to its default EEPROM. The dedicated DTS must not reference a nonexistent NVMEM provider. Mainline mt76 fallback remains a hardware-validation risk, not a promise of calibrated RF performance.
4. SPI bootloader location is not established by the current running kernel. No SPI write support or new partition layout is introduced.
5. Official LuCI package name is `luci-app-tailscale-community`.

## Verification Commands

1. `python3 -m unittest discover -s devices/sl3000_emmc/tests -v`
2. `bash -n devices/sl3000_emmc/firstboot.sh`
3. `actionlint .github/workflows/sl3000-emmc.yml`
4. In Linux: prepare pinned sources, `make defconfig`, then `verify.py config`.
5. In CI: `make download`, `make`, `verify.py artifacts` before any upload/release.
6. Hardware acceptance is a separate manual step. Never run `sysupgrade`, `dd`, `sgdisk`, or bootloader updates on the router in this task.

## Verification Record

- 14 Python tests passed on macOS, including a real shell execution of the partition guard.
- Workflow parsed successfully with actionlint 1.7.12; shell files checked with ShellCheck in Ubuntu 24.04.
- Pinned source/feed preparation completed in a Linux container. Real `make defconfig` and required built-in assertions passed.
- Feed provider assertions confirmed that all seven selected proxy core/helper recipes resolve to the pinned PassWall packages feed. Explicit uninstall/install is necessary; `feeds install -f` alone does not switch between feeds.
- DTS compiled against the checksum-verified Linux 6.12.94 source plus OpenWrt's MT7981 DTS completion patch. DTB reports `sl,3000-emmc` and 1 GiB RAM. Shared upstream DTS warnings remain; this is not hardware acceptance.
- No router writes, restarts, bootloader changes or partition changes were performed during implementation.
